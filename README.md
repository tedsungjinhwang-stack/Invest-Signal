# Invest-Signal

4시간봉 마감마다 **바이낸스 전체 USDT 무기한 + 레버리지 ETF**를 스캔해서
시그널이 뜨면 **텔레그램으로 알림**을 보내는 스캐너.

## 시그널 (크립토 모멘텀 눌림목/이탈만 15m봉, 나머지는 4h봉)

### 상승초입 (uptrend_onset)

1. **역배열** — `MA120 < MA240 < MA480` (`ma_align`, 짧은 선부터)

   > 선을 늘리거나 바꿀 수 있다 — `[120, 240, 480]` 10.56건/일·승률 65.8%,
   > `[120, 240]` 11.70·64.0%, `[240, 480]` 16.14·61.8%.
   >
   > 480을 빼면 최소 이력 요건이 480봉 → 240봉(40일)으로 내려가 **신규
   > 상장이 들어오지만**, 역배열 조건이 거의 걸러주지 못하게 된다: 374종
   > 최근 7일 실측으로 역배열 통과 봉이 68% → 77%로 오르고 발화가
   > 43.3 → 51.1건/일이 된다. 지금 시장이 통째로 역배열이라 두 선만으로는
   > 필터 구실을 못 한다. 이력이 모자라 판정에서 빠지는 종목은 3종이다.
2. **수퍼트렌드 상승** — 4h `supertrend(ATR 22 × 3)`가 상승추세(+1)
3. **20선 이탈** — 종가가 `ma_entry`(기본 20)선 아래
4. **월간 VWAP** — 최근 `vwap_touch_bars`(기본 5봉 = 20시간) 안에 캔들이
   MVWAP을 걸쳤거나(`저가 ≤ MVWAP ≤ 고가`) **또는** 종가가 MVWAP 위
   (`vwap_mode: any`). `vwap_period: M` — 매월 1일 UTC 리셋

②~④를 모두 만족하는 **첫 봉**에서 알린다. 아직 못 채운 이탈 봉은 발화하지
않고 대기하다가, 조건이 성립하는 봉에서 알린다. 상태를 벗어났다 다시
들어오면 새 시그널로 다시 알린다.

> **①과 ②를 함께 거는 게 이 시그널의 핵심이다** — 이동평균 구조는 아직
> 하락인데 추세(수퍼트렌드)는 이미 위로 돌아선 구간만 남는다. 그
> 상태에서의 첫 눌림이 타깃이다. 수퍼트렌드는 TradingView 내장
> `ta.supertrend`와 같은 정의(Wilder ATR + 트레일링 밴드)로 계산한다.

> **240선 터치 조건은 꺼져 있다**(`touch_condition: false`). 켜면 ① 앞에
> "역배열 상태에서 캔들이 240선을 걸친 봉이 `touch_window_bars`(60봉 =
> 10일) 안에 있을 것"이 붙고, '첫 봉'의 기준점도 그 터치가 된다.
> 뺀 이유는 터치와 발화가 사실상 분리돼 있었기 때문이다 — 740건을 재보면
> 발화 봉의 44%가 이미 240선 **위**였고 8%는 +5% 넘게 위였다. "최근 10일
> 안에 240선을 건드린 적 있나" 하는 자격 요건일 뿐, 알림 순간의 위치를
> 보장하지 못했다.

> **판정 방식은 `vwap_mode`** — `any`(기본, 터치 또는 위) / `touch`(터치만) /
> `above`(종가가 선 위만). `above` 단독은 알림을 크게 줄이면서 승률은 거의
> 안 올린다(7.58건/일·64.7% vs `any` 11.70·64.0%).
>
> 월간 앵커는 리셋 직후 선이 캔들 안에 파묻힌다 — **1일 첫 봉은 정의상
> 100%**(누적값이 그 봉 하나뿐이라 `MVWAP = (고+저+종)/3`), 첫날 76%,
> 2~3일차 40%가 캔들 범위 안이다. 그 구간의 "위/아래"는 종가가 자기 봉의
> 중간값보다 위인지를 묻는 것에 가깝고, 실제로 위/아래 상태는 종목당
> 4개월에 중앙 63회 뒤집힌다. 걸러낼 게 아니라 찾아야 할 상태였다.
>
> `vwap_touch_bars`는 터치를 인정할 소급 창이다(기본 5봉 = 20시간).
> `any`에서는 창 길이가 거의 영향이 없다 — `above` 쪽이 이미 대부분을
> 통과시키기 때문이다. `touch` 단독으로 쓸 때만 창이 유효한 레버가 되고,
> 그때는 짧을수록 승률이 높다.

**백테스트** (369종 4h, 04-08~08-11, MA480이 성립하는 480봉 이후 구간만.
크립토 설정 = VWAP 켬 + 랭크 필터 통과 후. 경로 승률 = ±10% 중 어느 쪽에
먼저 닿았는지):

| 조합 | 건/일 | 종목 | 도달률 | 경로 승률 | MAE중앙 |
|---|---|---|---|---|---|
| **120·240 + any 5봉 (현재)** | **11.70** | **161** | 23.5% | 64.0% | −5.6% |
| 120·240 + touch 5봉 | 9.56 | 143 | 24.8% | **65.3%** | −5.6% |
| 120·240 + above | 7.58 | 99 | 21.8% | 64.7% | −5.6% |
| 120·240·480 + any | 10.56 | 144 | 23.1% | **65.8%** | −5.6% |
| 240·480 + any | 16.14 | 178 | 24.6% | 61.8% | −5.5% |

수퍼트렌드 배수는 3.0이 가장 낫다 — 2.0은 8.51건/일·승률 59.3%,
4.0은 10.42건/일·승률 56.1%로 둘 다 나쁘다.

5. **크립토 랭크 필터 (완화판)** — 24h 거래대금 상위 `volume_top`(기본 200)
   또는 최근 3일 상승률 상위 `gain_top`(기본 100)에 들고, 24h 거래대금
   `min_turnover_usd`(기본 $1M) 이상. ETF·주식에는 적용하지 않는다

   > **④ VWAP 조건은 세 시장 모두 켜져 있다**(`vwap_condition: true`).
   > 예전엔 ETF·주식만 껐는데(종목이 적어 알림이 안 넘친다는 이유),
   > 유니버스가 47종이라 켜고 끄고의 알림 차이가 하루 1건 수준이다 —
   > 종목당으로 환산하면 켬 4.7건/일·승률 68.6% vs 끔 5.7건/일·62.5%.
   > 알림 부담은 사실상 같고 승률만 6%p 벌어져서 켜는 쪽으로 통일했다.
   > 시장별로 다시 가르려면 `crypto_vwap_condition`을 추가하면 된다.
   >
   > 단 위 수치는 **크립토 데이터를 종목당으로 환산한 추정치**다. 주식·ETF는
   > 장 마감과 갭 때문에 4h봉이 세션을 온전히 못 채우고 거래량 분포도 달라,
   > 앵커드 VWAP이 같은 정도로 작동한다는 보장은 없다.

### 눌림목 (pullback) — ETF·주식 전용

> **크립토에서는 돌지 않는다** (`crypto_enabled: false`). 크립토의 조정
> 자리는 ⚡크립토 모멘텀 눌림목/이탈이 15m봉으로 대신 본다. 되돌리려면 config에서
> `crypto_enabled: true`로 바꾸면 아래 크립토 랭크 필터와 함께 그대로
> 살아난다.

상승 추세 안의 조정 자리를 이동평균선만으로 잡는다.

1. **종가가 `ma_above`(기본 480)선 위** — 장기 추세는 살아 있어야 한다
2. **종가가 `ma_entry`(기본 60)선 하회** — 단기 조정에 들어감

위 두 조건이 전부다. 같은 하회 구간에서 **첫 봉 한 번만** 알리고,
60선 위로 복귀 후 다시 하회하면 새 눌림목으로 다시 알린다.

> **분기 VWAP 하단 밴드 조건은 꺼져 있다**(`band_condition: false`).
> 켜면 `분기VWAP − band_mult×σ` 밴드를 그려 캔들이 그 위에 있어야 하고,
> **대기**(캔들 전체가 밴드 위) / **🎯타점**(캔들이 밴드에 닿음) 두 단계로
> 나뉘어 각각 알림이 갔다. 밴드를 끄면 타점의 정의가 사라지므로 단계
> 구분도 함께 없어진다 — 알림에 대기/타점 태그가 붙지 않는다.

4. **크립토 랭크 필터 (주도주)** — 크립토는 **그 시기의 주도주만**:
   24h 거래대금 상위 `volume_top`(기본 200) **그리고**(`mode: and`)
   최근 14일(`gain_lookback_bars`, 84봉) 상승률 상위
   `gain_top_pct`(기본 10%)에 들고, 24h 거래대금이
   `min_turnover_usd`(기본 $1M) 이상이어야 알림. 진입 게이트를 공유하는
   **MSS 줄에도 동일하게 적용**된다. ETF·주식에는 적용하지 않는다

   > 373종 4h 데이터(2026-06-14~07-29) 백테스트로 정한 값이다. 종전
   > 기준(거래대금 상위 100 **또는** 3일 상승률 상위 50)은 알림을 3.0건/일로
   > 줄여줬을 뿐 선별력이 없었다(7일 내 +10% 도달률 46% — 무필터 45%와 사실상
   > 동일). 둘 다 요구하고 상승률 창을 3일→14일로 넓히면 2.4건/일·도달률 65%가
   > 된다. 창 길이는 12~18일이 모두 60% 이상인 고원이고 그 안에서 14일이
   > 가장 고르다 — 10일 이하는 눌림에 가려 표본이 급감하고, 21일 이상은
   > 표본 후반부 도달률이 43~45%로 무너진다.
   >
   > 거래대금 하한은 알림 수와 적중률을 맞바꾸는 축이다: $1M 2.4건/일·65%,
   > $2M 1.8건/일·67%, $5M 0.98건/일·74%. 하한을 아예 없애면 3.6건/일·57%로
   > 떨어진다. 반대로 **순위**로 조이는 건 효과가 없다 — 거래대금 상위 80위
   > 컷은 하한과 중복이라 결과가 한 건도 바뀌지 않고, 하한만 $20M 이상으로
   > 올리면 대형주만 남아 표본이 8건까지 줄어든다. 미국 IP에선 선물 API가
   > 막혀 현물 거래대금으로 재므로, 같은 하한이라도 퍼프 기준보다 빡빡하게
   > 걸린다(`BINANCE_PROXY`로 fapi를 쓰면 통과 종목이 늘어난다).

### 펌핑초기 (pump_early) — 크립토 전용 🌱

다른 시그널이 이미 오른 뒤의 눌림 자리를 잡는다면, 이건 그 앞 단계 —
**아직 크게 가지 않은 종목에 막 불이 붙는 봉**을 잡는다:

1. 최근 `rise_bars`(기본 1봉 = 4시간) 동안 **시가 대비 종가가
   `min_gain`(기본 +5%) 이상** 상승하고
2. 최근 `lookback_bars`(기본 42봉 = 7일) 안에 **하루(`pump_window_bars`,
   기본 6봉) 내 저점 → 고가가 `max_pump_gain`(기본 +30%) 이상 급등한 봉이
   없어야** 한다 — 하루 만에 확 오른 종목은 이미 '초기'가 아니다.
   급등 후 되돌린 종목도 이력만으로 제외된다
3. 같은 구간 **저점 대비 종가 상승률도 `max_gain`(기본 +30%) 미만** —
   하루 급등은 없었어도 누적으로 이미 크게 간 종목을 거른다
4. **종가가 `ma_ref`(기본 480)선 이하** — 장기선 위로 올라선 종목은 이미
   추세가 시작된 것이라 초입이 아니다. 480선을 계산하려면 480봉(80일)
   이상 이력이 필요하므로 **신규 상장은 자동 제외**된다
   (`below_ma_condition: false`로 끄면 위치·이력 조건 없이 판정)

**VWAP도 수퍼트렌드도 보지 않는다** — 급등 시작 포착이라 라인 위/아래나
추세 전환 여부를 따지지 않는다(상승초입·눌림목·하락전환은 수퍼트렌드가
꺾이면 추적에서 빠지지만, 이 시그널은 그렇지 않다).
연속 급등 구간에서는 첫 봉만 알리고, 추적은 종가가 **급등 봉의 저가를
지키는 동안** 유지 — 그 아래로 마감하면 되돌려진 것으로 보고 제거.
5% 급등은 흔하므로 **전용 크립토 랭크 필터**(기본: 거래대금 150위 또는
3일 상승률 100위, $3M 하한)로 알림량을 조절한다.

**인트라바 스캔**: 봉 마감 시각을 뺀 매시(`scan.yml`의 `intrabar` 모드,
봉당 3회)에 진행 중 봉을 포함해 스캔한다 —
펌핑초기(급등은 초기 포착이 목적이라 마감을 기다리면 늦다), 파동,
상승초입·눌림목(현재가를 잠정 종가로 판정)이 대상이며 알림에
**⏳진행봉** 태그가 붙는다. ⏳진행봉 알림은 봉 마감 때 조건이 풀리면
무효일 수 있고, 마감 후에도 유지되면 그대로 확정이다(같은 봉이라 재알림
없음). 하락전환·MSS는 마감 스캔에서만 판정.

**추적 목록은 인트라바에서도 그대로 싣는다.** 예전엔 인트라바에서 4h
시그널의 추적을 통째로 비웠다(진행봉 기준이라 잠정값이어서). 그러면
마감 스캔이 올 때만 목록이 보이니 4시간마다 메시지가 확 길어지고,
더 나쁘게는 **조건이 깨진 항목이 마감까지 최대 4시간 남아 있었다** —
수퍼트렌드가 꺾인 상승초입이 그랬다. 지금은 매시간 최신 상태로 갱신되고,
대신 4h봉 안에서 항목이 들락날락할 수 있다.

### 파동 (wave_setup) — 크립토 전용 🌊

수퍼트렌드 **두 개**로 잡는다. 공통 전제는 **장기(30 × 6)가 아직 하락**인
것이고, 단기(22 × 3)를 어떻게 건드리는지에 따라 두 변형으로 갈린다.
한 칸에 함께 뜨는데 **섞이지 않는다** — 추적 목록은 ⓐABC 블록 다음 ⓑ임펄스
블록으로 묶이고, 각 블록 안에서 24h 상승률 내림차순이다. 변형 이름은
블록 소제목에 한 번만 적는다(신규 줄은 몇 개 안 되므로 줄마다 태그로 단다).

두 변형 모두 **월간 앵커드 VWAP 조건**을 함께 통과해야 한다 — 상승초입과
같은 규칙(`vwap_mode: any` = 최근 `vwap_touch_bars`(5봉 = 20시간) 안에
캔들이 MVWAP을 걸쳤거나 **또는** 종가가 MVWAP 위).

> **두 변형 모두 4h 프레임의 MVWAP으로 잰다.** 같은 선을 보는 조건이고,
> 일봉으로 다시 계산하면 하루가 대표가격 하나로 뭉쳐져 터치 판정이
> 무뎌진다. 임펄스는 트리거 날짜의 **마지막 4h봉**을 기준점으로 쓴다.
>
> **지금 설정(`any`)에서는 거의 걸러 주지 않는다** — 374종 스냅샷에서
> 게이트 끔 18건 / `any` 18건으로 차이가 없었다. `touch` 단독은 16건,
> `above` 단독은 10건으로 줄어든다. 상승초입에서 이미 관측된 것과 같은
> 이유다(월간 앵커는 리셋 직후 선이 캔들 안에 파묻힌다). 조이려면
> `vwap_mode`를 바꾸면 된다.

**ⓐ ABC — 4h봉, 돌파** (`abc_enabled`)

1. 직전 봉에 단기·장기가 **둘 다 하락**이고
2. 이번 봉 종가가 **단기 추세선을 돌파해 마감**하고
3. 그 시점에도 **장기는 여전히 하락**

하락 구조 안에서 시작되는 반등(ABC 조정)의 첫 봉을 잡는다. 돌파를
"종가 > 단기선"으로 따로 재지 않고 **단기 수퍼트렌드가 그 봉에서 상승으로
뒤집혔는지**로 판정한다 — 수퍼트렌드는 종가가 상단 밴드(=하락 추세선)를
넘길 때 뒤집히므로 같은 사건이고, 트레일링까지 반영돼 선의 정의와 어긋나지
않는다. 뒤집힌 뒤 계속 상승이면 다시 알리지 않는다.

**ⓑ 임펄스 — 일봉, 터치** (`impulse_enabled`)

1. 일봉 단기·장기가 **둘 다 하락**인 채로
2. 캔들이 **단기 추세선을 터치**한 날 (`저가 ≤ 선 ≤ 고가`)

방향이 하락이면 단기선은 상단 밴드다. 종가가 그 선을 넘었다면 방향이
뒤집혀 여기 안 걸리므로, **터치와 돌파는 자동으로 갈린다**. 연속으로 닿는
날은 첫날만 알린다.

> **일봉은 따로 받지 않는다** — 스캔이 이미 가진 4h봉 6개를 묶어 만든다
> (4h봉은 UTC 00시에 맞춰 떨어진다). 아직 6봉이 안 찬 마지막 날은
> 미완성이라 버린다. 750봉 = 125일치라 일봉 수퍼트렌드에 충분하다.

**두 변형 모두 인트라바 스캔에서도 돈다**(매시간). 진행 중인 봉을 잠정
종가로 보고 판정하므로 알림에 **⏳진행봉**이 붙고, 봉 마감 때 조건이 풀리면
무효일 수 있다. ⓐ의 "돌파 후 마감"이 그래서 되돌려질 수 있는 판정이지만,
마감을 기다리면 최대 4시간이 늦는다.

> ⓑ는 인트라바에서 **진행 중인 오늘을 일봉에 포함**한다
> (`include_live_day`, 스캐너가 인트라바 모드에서 켠다). 안 그러면 오늘의
> 터치를 내일 UTC 00시가 지나서야 알게 되어 최대 하루가 묵는다. 그 봉의
> 고·저는 아직 자라는 중이라 판정이 뒤집힐 수 있다. 마감 스캔에서는 꺼져
> 있어 완성된 날만 본다.

**줄에는 4h·24h·7d 수익률이 함께 붙는다** — 이 시그널에만 있는 세트다
(다른 칸은 24h 하나). 신규·추적 양쪽 모두, 두 변형 모두 나온다.

> **추적 줄은 라벨 없이 `-0.7/+12/-6.8%` 한 덩어리로 적고, 배열 태그를
> 빼서 한 줄에 맞춘다.** 구간 순서는 블록 소제목(`4h/24h/7d`)이 한 번만
> 말해 주고, 배열은 이 시그널의 판정에 안 들어간다(수퍼트렌드로 잡는다).
> 라벨을 반복하고 배열까지 붙이면 줄이 62칸이 되어 폰에서 두 줄로 접혔다 —
> 지금은 37칸으로 다른 칸(41칸)과 같다. 못 구한 구간은 빼지 않고 `–`로
> 자리를 지킨다. 신규(•) 줄은 몇 개 안 되므로 라벨을 그대로 단다.

> 세 값 모두 **4h 프레임**에서 뽑는다. 7일 상승률은 종목의 성질이지 그
> 변형이 보는 차트 주기의 성질이 아니고, 일봉으로 재면 마지막 완성 봉이
> 이미 어제라 임펄스만 하루 묵은 값이 된다. 봉 개수가 아니라 **시각**으로
> 재므로(`pct_since`) 창이 길어도 이름 그대로의 기간이다.
>
> 추적 줄의 세 값도 `refresh_detail`이 매 스캔 갱신한다(이 훅이 하는 일은
> 그것뿐이다 — 수퍼트렌드선 값은 알림에 싣지 않으므로 다시 계산하지
> 않는다). 다른 시그널의
> 추적 줄이 24h만 싣는 이유가 이것 — 그쪽 `ret_4h`는 트리거 봉에
> 얼어붙은 값이라 며칠 지난 줄에 실으면 묵은 숫자가 나간다.

줄에는 **수퍼트렌드선 값도, 봉 주기도 적지 않는다**. 선 값은 매 줄 다른
숫자가 하나 더 붙을 뿐 판단에 쓰이지 않았고, 봉 주기는 ABC↔4h·임펄스↔일봉이
1:1이라 변형 이름이 이미 그 정보인 데다 같은 줄 수익률의 `4h`와 글자가 겹쳐
서로 다른 뜻으로 두 번 나온다.

> **추적 줄의 추세선은 매 스캔 다시 계산한다**(`refresh_detail`). detect가
> 붙인 값은 트리거 봉 기준이라, 며칠 전 터치한 종목이 그 사이 크게 빠지면
> `현재가 0.033 · 22×3선 0.241` 같은 줄이 나온다. 추세선은 지금 어디가
> 무효화 지점인지를 말해 줄 때 쓸모가 있다. 하락 추세의 밴드는 새 저점이
> 나올 때만 내려오므로 며칠째 같은 값인 것은 정상이다.

**ⓐ의 추적 보유 기간은 3일**이다(`abc_track_days`) — 다른 시그널의 공용
창(`scanner.TRACK_DAYS` = 5일)보다 짧다. 돌파는 4h짜리 사건이라 며칠
지나면 '방금 돌파한 자리'가 아니게 된다. ⓑ는 일봉 터치라 성격이 달라
공용 창을 그대로 쓴다. `0`으로 두면 캡이 없어져 ⓐ도 5일이 된다.

추적은 그 안에서 **트리거 조건이 살아 있는 동안**만 유지된다. 둘 다 장기가
상승으로 뒤집히면 빠지고, 거기에 ⓐ는 단기가 다시 하락으로 밀리면(돌파
실패), ⓑ는 단기가 상승으로 뒤집히면(더 이상 터치 자리가 아니다 — 그
사건은 ⓐ가 따로 잡는다) 빠진다.

### 크립토 모멘텀 눌림목/이탈 (leader_break) — 크립토 전용 ⚡

**유일하게 4h봉이 아닌 시그널이다 — 15분봉으로 판정한다.**

1. **24시간 상승률 상위 `top_n`(기본 15)종**을 매 스캔 새로 뽑고
2. 그중 **4h가 정배열인 종목만** 남긴 뒤 (아래 제외 규칙)
3. **15분봉 종가가 `ma`(기본 20)선을 하향 이탈하는 첫 봉**에서 알림

칸 맨 위에는 **24h 상승률 상위 `board_top`(기본 5)종을 조건 없이** 먼저
적는다. 이탈했든 안 했든, 제외 필터에 걸렸든 아니든 순위 그대로다 —
"지금 뭐가 오르고 있나"를 한눈에 보라는 목록이고, 그 아래가 실제로 조건을
충족한 알림이다.

```
📈 24h 상승률 TOP
1. TUT   0.06324 · +81%      ← 조건 무관, 순위 그대로
2. MMT   0.2312  · +36%
...
🪙 크립토
• BICO  0.05633 · 24h +22% · 15m 20SMA 0.0566077 이탈   ← 조건 충족
↳ TUT   0.06179 · 1위·20선 위·24h +81%                  ← 추적
```

20봉 × 15분 = **5시간**짜리 단기 추세선이다. 하루 사이 가장 많이 오른
종목이 그 선을 깨는 자리 — 주도주의 단기 모멘텀이 꺾이는 지점을 잡는다.

> 선을 짧게 잡을수록 이탈이 잦아진다. 현재 상위 10종의 최근 400봉(≈4일)을
> 재보면 **20MA 287회 vs 60MA 132회로 2.2배**다. 알림이 과하면 `ma`를
> 키우는 게 가장 직접적인 레버다.

대상 선정은 바이낸스 **24hr 티커**(전 종목 1회 요청)로 한다. 캔들로
역산하면 마지막 마감된 4h봉 기준이라 최대 4시간 묵은 순위가 되지만,
이 엔드포인트는 호출 시점 기준 롤링 24시간이라 지연이 없다.

`min_turnover_usd`(기본 $1M) 하한을 넘는 종목만 후보다. 0으로 두면 순수
상승률 상위 15종이 되는데, 그러면 거래가 거의 없는 잡코인이 상위권을
채운다(눌림목 필터에서 확인된 것과 같은 현상). **하한은 이월분(감시 창에
남은 종목)에도 적용된다** — 상위권에 들 땐 넘었어도 그 뒤 거래가
말라붙는 종목이 많고, 그대로 두면 `max_watch` 슬롯을 차지해 더 최근
상위권 종목을 밀어낸다(실측: 이월 45종 중 14종이 $1M 미만이었다).

**4h 구조로 두 번 거른다** (`blocked()`):

1. **정배열이 아니면 제외** (`require_aligned`) — 24h 상승률 상위라도 4h가
   역배열·혼조면 그 상승은 하락 추세 안의 반등이거나 방향이 아직 안 잡힌
   것이다. 주도주의 눌림으로 볼 자리가 아니다.
2. **정배열이어도 종가가 `exhausted_below`(기본 480)선 아래면 제외**
   (`exhausted_filter`) — 상승 구조가 완성된 상태에서 480선까지 밀렸으면
   오를 만큼 오르고 꺾인 것이라 새로 잡을 눌림이 아니다.

**컷이 세다.** 실측(2026-08-14 스캔)에서 감시 대상 60종 중 **45종이 잘렸다**.
24h 상승률 상위 25종만 봐도 정배열 5 · 역배열 13 · 혼조 6 · 이력부족 1이라,
`top_n: 15`를 걸어도 실제로 15m을 보는 건 서너 종에 그치는 날이 많다.
걸리는 사유는 거의 전부 **역배열·혼조**이고 이력 부족은 1% 남짓이다.

> **신규 상장은 빠진다 — 다만 해당 종목이 많지는 않다.** MA480은 480봉(80일)이
> 있어야 성립하고, 그 전에는 `alignment()`가 None을 줘서 ①에 걸린다.
> 실측(2026-08-14, 유니버스 374종)에서 **480봉 미만은 3종(1%)** 뿐이었다 —
> 거래대금 $1M 이상 중에는 RE(336봉·56일)와 GRAM(253봉·42일) 둘이다.
> 통과시키려면 `allow_short_history: true`. (판정이 되는데 정배열이 아닌
> 경우는 이 설정과 무관하게 그대로 제외된다.)
>
> 상승초입은 240봉(40일)만 있으면 되므로 이 구간을 대신 잡는다 — 위 두
> 종목 모두 상승초입 대상이다. 유니버스 전체에서 240봉 미만은 1종뿐이다.
>
> 봉 수는 **데이터 출처의 상장일**을 따른다. 미국 IP에선 fapi가 막혀 현물
> 미러로 받으므로 현물 상장일 기준이고, `BINANCE_PROXY`로 퍼프를 쓰면
> 퍼프 상장일 기준이라 숫자가 달라질 수 있다.

> 4h 조회 실패는 제외하지 않는다 — 네트워크 문제로 주도주가 통째로
> 사라지면 안 되니, 판단 자체가 불가능한 경우만 통과로 둔다.

> 판정에는 4h 프레임을 쓴다. 스캔이 이미 받아온 750봉을 재사용하고,
> 없으면(인트라바에 4h 대상 시그널이 없는 경우) 해당 종목만 따로 받는다.

**한 번 상위권에 든 종목은 순위에서 밀려나도 `watch_days`(기본 5일) 동안
계속 확인하고, 그동안 `↳ 추적 리스트`에 남는다.** 상위권은 하루에도 여러
번 바뀌어서, 밀리자마자 눈을 떼면 정작 꺾이는 순간을 놓친다. 마지막 등재
시각은 상태 파일의 `leaders`에 남고, 창을 벗어나면 자동으로 정리된다.
매 스캔 캔들을 받아야 하므로 총량은 `max_watch`(기본 60종)로 묶고,
넘치면 최근 등재 순으로 남긴다.

**추적 목록도 이탈 조건을 그대로 받는다**(`track_break_only: true`) —
지금 ma선 아래인 종목만 남고, 선 위로 복귀하면 빠진다. 다른 시그널의
추적과 같은 뜻이 된다: '조건이 아직 살아 있는 셋업'.

```
↳ STG   0.1433  · 7위·🔻20선 아래·24h +14%     ← 지금도 상위권 + 이탈 상태
↳ ETH   1,913.6 · 추적 3일차·🔻20선 아래·24h -0%  ← 밀린 지 3일, 아직 이탈
```

상위권이면 **순위**, 밀렸으면 **추적 N일차**가 앞에 붙는다.
`track_break_only: false`로 두면 예전처럼 감시 창 안의 전 종목을 선
위/아래 상관없이 상태만 표시한다(그때는 `20선 위` 줄도 섞여 나온다).

4h 프레임을 쓰지 않으므로 **마감·인트라바 스캔 양쪽에서 매번** 돈다 —
1시간 간격 스캔 기준으로 시간당 한 번 확인된다. `grace_bars`(기본 4봉 =
1시간)만큼 소급 판정하므로 스캔 사이에 지나간 봉의 이탈도 놓치지 않는다.
선 아래에 머무는 동안은 재알림하지 않고, 위로 복귀했다가 다시 깨면 새
이탈로 다시 알린다. 크립토 랭크 필터는 적용하지 않는다(자체 선정이라).

### 하락전환 (downtrend_reversal) — bearish CHoCH

1. 종가가 **60선 아래로 눌렸던 구간**이 완성되고 (종가가 60선 위로 복귀)
2. 그 구간의 **최저 저가(꼬리 포함) = 직전저점**을 기준으로
3. 이후 `lookback_bars`(기본 180봉 = 30일) 안에 종가가 직전저점 아래로
   마감하면서 **분기 VWAP(QVWAP) 아래에 있는 첫 봉**에서 알림 —
   상승초입의 거울 대칭으로, QVWAP 선이 캔들 아래에 있다가 위로 확
   올라온 상태의 구조 붕괴만 인정한다. 저점을 깼는데 아직 QVWAP 위면
   대기 (`qvwap_condition: false`면 저점 이탈만 본다). 상승초입이 월간
   앵커로 옮겨간 것과 달리 **여기는 분기 그대로**이고, 수퍼트렌드 조건도
   없다

진행 중인 눌림 안에서 저점을 갱신하는 것은 돌파로 치지 않는다 — 완성된
직전저점의 하향돌파(ICT의 CHoCH)만 잡는다.

**ETF·주식만 🔻하락전환 칸에 표시**된다. 크립토는 표시하지 않고, 눌림목
항목을 추적 리스트에서 제거하는 용도로만 쓴다.

### MSS (mss) — ETF·주식 전용

> 눌림목 칸에 태그로 붙는 줄이라 **크립토에서는 눌림목과 함께 빠진다**
> (`crypto_enabled: false`). 눌림목 진입 게이트를 통과해야 성립하는
> 표시라 단독으로 남겨둘 수 없다.

**진입 조건은 눌림목과 완전히 동일**하고(480선 위 + 60선 하회 —
config의 `pullback` 설정을 그대로 공유), 그 위에
**직전 스윙저점**(좌우 `pivot_k`=6봉(24시간)보다 낮은 저가로 확정된
저점)을 종가가 하향돌파하는 프라이스 액션이 있으면 ⚠️MSS로 표기한다.
눌림목 후보가 아닌 저점 이탈은 표시하지 않는다. 첫 돌파 봉만 알리고
저점 위로 복귀 후 재돌파하면 다시 알린다.

### 알림 메시지 구성

- **신규 시그널**: 시그널별(🟢상승초입 🔵눌림목 🌱펌핑초기 🌊파동 ⚡크립토 모멘텀 눌림목/이탈
  🔻하락전환 — MSS는 눌림목 칸에 태그, 펌핑초기·파동·크립토 모멘텀 눌림목/이탈은 크립토만,
  눌림목·MSS·하락전환은 ETF·주식만)

  > **🟢상승초입·⚡크립토 모멘텀 줄에는 종목의 1h·4h·24h 수익률**이 함께 붙는다:
  > `• ORDI 3.466 · 1h -0.1% · 4h -0.6% · 24h -0.6% · 혼조`
  >
  > 구간마다 출처가 다르다. ⚡는 15m봉이라 1h(4봉)·4h(16봉)를 그 자리에서
  > 계산한다. 🟢는 4h봉이라 4h(1봉)·24h(6봉)만 나오고, **1h는 알림 대상 몇
  > 종만 따로 1h 캔들을 받아** 채운다(크립토) — ETF·주식은 원본이 1h봉이라
  > 추가 요청이 없다. 24h는 바이낸스 24hr 티커 값이 있으면 그쪽을 쓴다
  > (캔들 역산은 최대 4시간 묵지만 티커는 호출 시점 롤링이다).
  > 구할 수 없는 구간은 0%로 채우지 않고 그냥 뺀다.
  → 그 아래 [크립토]/[ETF]/[주식] 그룹.
  크립토는 USDT 접미사 없이 표기, 차트 링크·배열 상태 포함
- **↳ 추적 리스트**: 각 시그널·시장 칸 아래 한 줄 —
  `심볼 현재가 · 경과일d · 24h 수익률 · 배열`

  > **정렬은 24h 수익률 내림차순**이다 — 셋업이 지금 먹히는 종목이 맨 위로
  > 온다. 🌊파동은 그 앞에 **변형(ABC → 임펄스)으로 먼저 묶고** 블록마다
  > 소제목을 단다 — 4h 돌파와 일봉 터치가 번갈아 나오면 읽기 어렵고,
  > 서른 줄 내내 같은 변형 이름이 붙으면 정작 다른 값이 눈에 안 들어온다.
  > 신규(•) 줄도 같은 순서를 따른다.
  >
  > 태그 구분자는 신규 줄과 같은 ` · `다. 예전엔 추적 줄만 붙여 쓴 `·`라
  > 한 줄 안에서 `0d·4h -3.1% · 24h`처럼 두 방식이 섞였다.
  >
  > 발생 시각순이던 것을 바꾼 것으로, 스무 줄짜리 목록에서 볼 줄을
  > 먼저 보이게 하려는 것이다. 못 구한 항목은 0%로 채우지 않고 맨 아래로
  > 내리고, 그 안에서만 최신 발생 순이다.
  >
  > **거래대금순은 쓰지 않는다.** 표시되는 종목은 전부 랭크 필터의 하드
  > 하한(`min_turnover_usd`)을 이미 통과했으므로 다시 줄 세워도 새 정보가
  > 없다. 반면 상승률은 `mode: or`에서 거래대금으로 통과한 종목을 보지도
  > 않으므로 화면에서 처음 드러나는 값이다.
  >
  > 값은 신규 줄과 같은 규칙 — 바이낸스 24hr 티커가 있으면 그쪽,
  > 없으면 4h봉 6개 역산. 단 **detect 시점 값을 그대로 쓰지 않는다**:
  > 사흘 전 셋업이면 사흘 전 수익률이 박제돼 있어, 매 스캔 마지막 봉
  > 기준으로 다시 계산해 덮어쓴다.
  - 상승초입: 발생 후 계속 추적(이탈선 위 복귀해도 유지). 제거는
    **수퍼트렌드가 하락으로 뒤집힐 때** 하나뿐 — 진입 전제가 사라진
    것이라 진입 조건이자 해제 조건이다. CHoCH로도, 240선 돌파 실패로도
    제거하지 않는다
  - 눌림목: 발생 후 계속 표시 — 60선 위로 복귀해 올라가는 동안도 추적하며,
    **하락전환(CHoCH)이 나오거나, 종가가 480선 아래로 마감하거나,
    수퍼트렌드가 하락으로 뒤집히면 제거**된다 (밴드를 켜면 밴드 이탈도
    제거 조건에 더해진다)
  - 펌핑초기: 종가가 급등 봉의 저가 위에서 버티는 동안. **수퍼트렌드는
    보지 않는다** — 급등 시작 포착이라 추세 전환을 기다리면 이미 늦다
  - 파동: 트리거 조건이 그대로 살아 있는 동안 — 장기 수퍼트렌드가 상승
    전환하면 둘 다 빠지고, ABC는 단기가 다시 하락하면(돌파 실패),
    임펄스는 단기가 상승 전환하면 빠진다
  - 하락전환: 종가가 계속 깨진 직전저점 아래인 동안 추적. **수퍼트렌드가
    상승으로 뒤집히면 제거** — 거울 방향이다(이 시그널의 전제가 하락이라)
  - MSS: 종가가 계속 깨진 직전저점 아래인 동안 (경고 마커로 병행 표시)
  - 크립토 모멘텀 눌림목/이탈: **감시 창(기본 5일) 안이면 무조건 유지** —
    다른 시그널과 달리 조건이 풀려도(선 위로 복귀) 빠지지 않고 상태만
    바뀐다. 창이 끝나야 사라진다
  - 보유 기간은 **5일**(`scanner.TRACK_DAYS`, 4h 30봉) — 조건이 살아 있어도
    그 뒤엔 자동으로 빠진다. 그 안의 항목은 **자르지 않고 전부 표시**하며,
    길어지면 텔레그램 길이 제한에 맞춰 여러 메시지로 나눠 보낸다
- **크립토 하락전환은 표시하지 않음** — 셋업 이후 하락전환이 발생한 종목의
  눌림목 항목을 추적 리스트에서 영구 제거하는 역할만 한다

시그널마다 config에서 **시장별로 끄거나 다르게 돌릴 수 있다**:
`enabled: false`는 전면 중단, `crypto_enabled: false`는 크립토에서만 빼고
ETF·주식에서는 유지한다(크립토 전용 시그널은 모듈의 `CRYPTO_ONLY`로 반대
방향을 막는다). 파라미터 값 자체를 시장별로 가르려면 **`crypto_<키>`**를
같이 두면 된다 — 크립토 스캔만 그 값을 쓰고 ETF·주식은 공용 값을 쓴다
(예: `vwap_condition: false` + `crypto_vwap_condition: true`).

새 시그널은 `invest_signal/signals/`에 모듈을 추가하고 `config.py`의
`detectors()`에 등록하면 된다. 단 `detectors()`는 **4h 프레임을 받는
시그널 전용**이다 — 크립토 모멘텀 눌림목/이탈처럼 다른 봉이나 횡단면 순위가 필요하면
`scanner.scan_crypto` 안에서 별도 단계로 붙인다
(`_scan_leader_break` 참고).

## 바이낸스 지역 차단(451)과 데이터 소스

GitHub Actions 러너(미국 IP) 실측 결과:

| 엔드포인트 | 결과 |
|---|---|
| `fapi.binance.com` (선물) | ❌ HTTP 451 |
| `api.binance.com` (현물) | ❌ HTTP 451 |
| `data-api.binance.vision` (공식 현물 데이터 미러) | ✅ 200 |

`crypto.source: auto`(기본)는 **fapi 시도 → 실패하면 현물 미러로 자동
폴백**한다. 현물·무기한의 4h 가격은 MA 시그널 용도로는 사실상 동일하다.
폴백 시 현물 USDT 페어 중 **퍼프 상장 이력이 없는 현물 전용 코인(ADX 등)은
제외**한다 — 공식 데이터 저장소(data.binance.vision S3, 미국에서도 접근
가능)의 USDT-M 선물 심볼 목록과 교집합(실측 460종 → 373종). 단, 커버리지
차이가 있다(실측): 활성 USDT 퍼프 787종 중 현물로 커버되는 건 377종(48%)
— 나머지는 토큰화 주식 퍼프, 퍼프 전용 밈코인, 현물 상폐 코인 등.
BTC·ETH·SOL 등 주요 코인은 전부 커버된다. 진짜 무기한 데이터로 돌리려면:

- `BINANCE_PROXY` 시크릿에 **비미국 HTTP/SOCKS 프록시**를 넣거나
  (`http://user:pass@ip:port` 또는 `socks5h://user:pass@ip:port` —
  ISP 프록시 등. fapi 요청만 프록시로 나가고 현물 미러·S3 폴백 경로는
  직결 유지라 프록시가 죽어도 스캔은 계속 돈다), 또는
- `BINANCE_FAPI_BASE` 시크릿에 fapi로 포워딩하는 비미국 리버스프록시
  주소를 넣거나
- 한국 PC/서버에서 crontab으로 실행 (`--only crypto`)

## 설정

### 1. 텔레그램 봇 (필수)

1. [@BotFather](https://t.me/BotFather)에서 봇 생성 → 토큰 복사
2. 봇에게 아무 메시지 전송 후 `https://api.telegram.org/bot<토큰>/getUpdates`에서
   `chat.id` 확인
3. 레포 Settings → Secrets and variables → Actions에 등록:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`

시크릿이 비어 있으면 스캔 워크플로가 **즉시 실패**한다(빨간 런) — 알림이
조용히 증발하는 것을 막기 위한 안전장치다. 발송에 실패한 시그널은 상태에
기록하지 않으므로 다음 4h 스캔에서 한 번 더 시도된다(`grace_bars`).

### 2. 스케줄

`scan.yml` **하나**가 매시 :07에 돌면서, 실행 시각의 UTC 시(hour)를 보고
모드를 스스로 고른다 — 하루 24회.

| 시각(KST) | 모드 | 판정 |
|---|---|---|
| 01·05·09·13·17·21시 | `close` | 4h봉 **마감** 직후 — 전 시그널 |
| 나머지 18개 시간 | `intrabar` | **진행봉** 포함 — 상승초입·눌림목·펌핑초기·파동 |

마감 시각에는 인트라바를 돌리지 않는다. 그때의 진행봉은 막 열린 봉이라
잠정 종가로 쓸 값이 없기 때문이다. 봉 하나를 +1h/+2h/+3h 세 번 보게
되므로 셋업을 더 일찍 잡는 대신, 마감 전에 되돌아갈 일시적 상태도 함께
잡힌다(⏳진행봉 태그로 구분되고, 같은 봉은 재알림되지 않는다).
크립토 모멘텀 눌림목/이탈은 15m봉이라 두 모드 모두에서 매번 돈다.

워크플로를 하나로 합친 이유는 **외부 크론을 URL 하나로 끝내기 위해서**다
(아래 참고). 수동 실행 시에는 `workflow_dispatch`의 `mode` 입력으로
`close`/`intrabar`를 직접 고를 수 있고, 기본값 `auto`가 위 표대로 고른다.

중복 알림은 `state/alerts_state.json`으로 방지하며 실행 후 자동 커밋된다.
`scan.yml`을 수정해 푸시하면 즉시 1회 실행된다(수동 실행 대용).

#### 발송 기록 (`state/sent_log.jsonl`)

**보낸 메시지 원문을 30일치 남긴다.** 상태 파일에는 `종목|시그널|봉시각`만
들어 있어서 "무엇이 언제 잡혔나"까지만 알 수 있다 — 가격·수익률 태그·
📈순위표·추적(↳) 줄은 렌더링 결과라 어디에도 안 남는다. 나중에 되짚으려면
원문이 필요해서 따로 기록한다.

```bash
python -m invest_signal --history        # 최근 5건 (HTML 태그 제거)
python -m invest_signal --history 20     # 최근 20건
python -m invest_signal --history --raw  # 태그 그대로
```

```
═══ 2026-08-13 16:20 KST · close · crypto 1 hold 102
🚨 4h 시그널 · 08-13 16:20 KST
🟢 상승초입
🪙 크립토
• ORDI  3.466 · 1h -0.1% · 4h -0.6% · 24h -0.6% · 혼조
```

JSONL 한 줄이 발송 한 건이다(`ts`·`mode`·`counts`·`text`). **발송이 확인된
경우에만** 쌓이므로 dry-run이나 발송 실패는 안 들어간다. 30일이 지났거나
500건을 넘으면 다음 기록 때 오래된 것부터 자동으로 정리된다. 커밋 스텝이
`git add state/`로 디렉터리째 담으므로 워크플로 수정 없이 함께 올라간다.
기록 실패는 로그만 남기고 넘어간다 — 알림은 이미 나간 뒤라 사본 때문에
스캔을 실패시킬 이유가 없다.

#### 크론 지연과 외부 트리거

**`schedule` 실행은 정시에 오지 않는다.**(아래 참고 — 지금은 안 쓴다.)
`:01`분에 걸었을 때 최근 20회가
크론 시각 대비 **+17~175분(중앙값 ~50분)** 늦었다. GitHub 문서는 schedule
이벤트가 부하에 밀릴 수 있고 **매시 정각이 그 피크**라고 명시한다 —
`:01`은 정확히 그 자리였다.

그래서 크론을 **`:07`분으로 옮겼다.** 공짜로 해볼 수 있는 완화책이지
해결책은 아니다 — 여전히 schedule 큐 안이고, 얼마나 줄지는 며칠 돌려
`:01` 시절 기록과 비교해 봐야 안다. 마감 스캔이 봉 마감 7분 뒤가 되지만
판정은 마감된 봉으로 하므로 결과는 같고 알림만 그만큼 늦게 온다.

밀리는 건 **실행이 생성되는 시점**뿐이다. 측정해 보면:

| 이벤트 | 크론 시각 → 생성 | 생성 → 시작 |
|---|---|---|
| `schedule` (29건) | +17~175분 | **0초** |
| `push` (1건) | 해당 없음 | **0초** |

즉 러너 대기열은 병목이 아니다. `workflow_dispatch`·`repository_dispatch`
같은 **API 트리거는 push와 같은 경로라 호출 즉시 실행이 생성된다.** 외부
크론이 정시에 API를 때리면 이 지연이 사라진다. 스캔·알림은 그대로
Actions에서 돌고 외부 서비스는 **신호만** 보낸다(별도 서버 불필요).

워크플로가 하나뿐이므로 등록할 크론 잡도 **하나**다 — 스케줄
`0 * * * *`에 아래 한 줄:

```bash
curl -X POST -H "Authorization: Bearer $PAT" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/tedsungjinhwang-stack/Invest-Signal/actions/workflows/scan.yml/dispatches \
  -d '{"ref":"claude/signal-alarm-feature-yo698c"}'
```

PAT는 fine-grained로 이 레포에만, **Actions: Read and write** 권한 하나면
된다. 모드(마감/인트라바)는 워크플로가 UTC 시를 보고 알아서 고르므로
호출 쪽에서 구분할 필요가 없다.

> 남는 변수는 **외부 서비스 자신의 정시성**이다. 그쪽이 늦게 쏘면 그만큼
> 그대로 늦는다 — 등록 후 그 서비스의 실행 이력에서 실제 발사 시각을
> 확인하면 된다. 그리고 dispatch 지연이 실제로 0에 가까운지는 GitHub
> 실행 목록에서 `workflow_dispatch` 이벤트의 크론 시각 대비 생성 시각으로
> 검증할 수 있다(위 표는 `schedule`·`push` 실측이고 dispatch는 미측정).

#### `schedule:` 블록은 제거했다 — 매시 알림이 두 번 나갔다

보험으로 남겨 뒀는데 외부 크론과 겹쳐 **매시 두 번 알림이 갔다.** 외부
크론은 :02에 정확히 도는 반면 schedule은 :16~:58 사이 아무 데나 떨어져서,
같은 시간대에 알림이 두 번 오는 것처럼 보였다:

```
08-13  ... 17:03(20)  17:29(5)   18:02(13)  19:02(15)  19:17(3)
           ↑외부크론  ↑schedule  ↑외부크론  ↑외부크론  ↑schedule
```

**dedup으로는 안 걸러진다.** `bar_time` 기반 중복 방지는 *같은 봉의 같은
셋업*만 막는데, 15~50분 뒤에 도는 두 번째 실행은 15m봉이 몇 개 더 마감된
상태라 ⚡크립토 모멘텀에서 **진짜 새로운 이탈**을 찾아낸다. 중복이 아니라
별개 알림이라서 정상 동작이지만, 받는 쪽에서는 "한 시간에 두 번"이다.

이제 외부 크론 하나만 남는다. 그쪽이 죽으면 알림이 조용히 끊기는 게
단점이지만, 매시 중복 발송보다는 낫다. 되살리려면 `on:`에 다시 넣으면
되고, 그때는 두 번 오는 걸 감수해야 한다.

### 3. 로컬 실행

```bash
pip install -r requirements.txt
python -m invest_signal --dry-run          # 발송 없이 결과만 출력
python -m invest_signal --only crypto      # 크립토만
python -m invest_signal --history 10       # 최근 발송된 알림 원문 10건
TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... python -m invest_signal
```

### 4. config.yaml

```yaml
signal:
  uptrend_onset:
    enabled: true
    ma_align: [120, 240]       # 역배열 판정선 (짧은 것부터)
    ma_entry: 20               # 이탈 판정 기준선 — 4h×20 ≈ 3.3일
    grace_bars: 1              # 스캔 한 번 놓쳤을 때 소급 허용 봉 수
    touch_condition: false     # 240선 터치 요구 (끔)
    supertrend_condition: true # 수퍼트렌드 상승추세 요구
    st_period: 22              # 수퍼트렌드 ATR 기간
    st_mult: 3.0               # 수퍼트렌드 ATR 배수
    vwap_period: M             # 앵커드 VWAP 리셋 주기 — M/Q/W
    vwap_mode: any             # any / touch / above
    vwap_touch_bars: 5         # 터치 소급 창(봉) — 5봉 = 20시간
    vwap_condition: true       # VWAP 조건 사용 여부 (세 시장 공통)
  pullback:
    enabled: true
    ma_entry: 120              # 하회 판정 기준선
    grace_bars: 1
crypto:
  source: auto                 # auto | fapi | spot_mirror
  exclude: []                  # 제외 심볼
etf:
  tickers: [...]               # 코드/시장/이름
```

의존성은 `requirements.txt`에 정확히 고정돼 있다(무인 크론이라 상위
버전이 갑자기 깨는 것을 방지). 올릴 때는 테스트 후 갱신할 것.
